# Schematic-Cicada

> Windows 单机桌面 EDA 助手：**一个窗口 = 左原理图画布 + 右 AI 对话**。
> 人画图 AI 感知，AI 画图人确认，导出 KiCad 直接打开的 `.kicad_sch`。

目标不是"AI 帮你查资料"，而是**让 AI 真的把一块电路画出来**：你描述需求，它澄清、研究、取资料、落图、连线；你在画布上确认与微调，最后导出可在 KiCad 里打开、网表可用的原理图。纯本地单机，不联网也能用（联网时才会去检索资料）。

配套仓库：**[Schematic-Cicada-Harness](https://github.com/86thAuspiciousVerse/Schematic-Cicada-Harness)** —— AI 管道（角色契约、知识图景、数据手册流水线、流程编排）实现在定制 DSH 里，位于那边。

## 1. 核心工作流

### 用户视角

```
描述需求              澄清                等它干活              画布确认            导出
"做一个 stm32     →   问答式确认：     →   AI 研究 / 取资料  →   人看画布：挪元件、 →  .kicad_sch
 最小系统，含           MCU 型号、           / 落图 / 连线          改位置、补连线      （KiCad 打开、
 5V→3.3V 稳压"         功能范围、时钟                                （人与 AI 互斥）     网表可用）
```

### 系统视角：一次完整跑的四段

| 阶段 | 谁在做 | 产物 | 这一段在做什么 |
|---|---|---|---|
| ① 澄清 | 主编排（对话） | 已确认需求 | 把会改变结果的问题问清（型号、范围、时钟、电源来源…）；无人应答时按最保守默认继续，并列出假设清单 |
| ② 知识图景 | **knowledge 子代理** | `.cicada/design_intent.json` | 检索并推理出"这块板子由哪些功能块、哪些件、什么参数构成"；参数是结构化的（名称/取值/约束强度/来源），通用无源件只写设计方向、不列成"待取资料的件" |
| ③ 数据手册道 | **datasheet 子代理** | `datasheet/<型号>/{index.json, detail/<组>.json, shape.json}` | 按**功能**把数据手册切组（电源/时钟/复位与启动/调试/各外设…），每组写清"这组有什么、来自哪张表、承载什么约束"，并把"要外接什么、多大、怎么接"落成可机读字段；引脚带功能说明，每条结论带逐字证据锚点 |
| ④ 落图 | **producer 子代理** | `.cicada/schematic.cicada_sch` + 台账 | 先读图景，再按功能组取事实（组描述/外接元件/工作限值/引脚功能），用八件写工具放件、连线、打标签、放电源符号、标未用脚；每画一组记一条决策台账 |

**资料复用优先**：先查共享数据手册库；命中就直接把三件套复制进工作区（不重跑抽取），未命中才去抽取 PDF、产出三件套、过审计后入库，供之后所有项目复用。

**人在环**：AI 编辑期间画布加锁——AI 写时人不能改，人改时拒绝 AI 的写工具（引擎另有文件哈希双保险）；撤销只撤人类操作，AI 的写入是撤销边界。确认无误后一键导出 `.kicad_sch`。

## 2. 我们做了什么

### 引擎（`cicada-editor/`，C++，抽取的 KiCad 内核）
- 把 KiCad 的解析 / 几何 / 连接性内核抽成**无 GUI 的本地 HTTP 服务**（场景、算子、文档、导出、库），只绑 127.0.0.1 + 令牌，动态端口。
- **确定性符号合成**：数据手册 → 形状块（`shape.json`）→ 引擎生成用户库符号。引脚位置、角度、电气类型全由引擎算，AI 不碰几何。
- 库键归一（`R`、`R:R`、文件里的各种写法归一到同一键）；导出内嵌 `lib_symbols`，KiCad 可直接打开。

### 启动器（`cicada-shell/`，Electron）
- 六个页面：**开始 / 项目 / 资料库 / 符号库 / 运行 / 设置**；项目根 = `<CICADA_HOME>/projects/<名字>/`。
- **资料库页**：共享数据手册库的只读浏览——组描述、源锚点、"外接元件（取值 / 连接方式 / 为什么）"、工作限值、引脚功能、结论溯源；支持导出与删除（删除进回收站）。
- **符号库页**：精选库（只读）与用户库（可写）两栏，引脚几何一律来自引擎。
- **运行页**：实时会话控制台；启动器负责拉起并监督引擎与 AI 宿主，产品窗口关闭后回到启动器。

### AI 管道（配套 harness 仓库）
- 四个角色（主编排 / knowledge / datasheet / producer）各有自己的剧本与 persona，子代理拿到的是**本职工具**：查库、抽取、派单、直接写文件对它们关闭；knowledge 不能读工作区里的数据手册，知识图景只有它能写。
- 图景以**结构化方式**交给 producer（而不是让主编排抄成一段散文），并且明确了取值来源的优先顺序。
- 数据手册三件套与知识图景都有契约与审计：组要自述、结论要有逐字证据、引脚归属唯一、形状块身份必须等于件号——不合格就拒绝入库。

### 精选符号库（`assets/cicada-libs/`）
官方 `.kicad_sym` 子集（常用阻容/电源/接口等），配合"数据手册 → 形状块 → 确定性合成"覆盖 IC 类器件。

## 3. 仓库结构

```
cicada-editor/     引擎（C++ 服务 + KiCad 桥 + 脚本 + 测试）
cicada-shell/      Electron 启动器（项目 / 资料库 / 符号库 / 运行 / 设置）
assets/            精选符号库与资产说明
datasheet-example/ 形状块样例（AMS1117-3.3：数据手册 → 引脚形状）
```

`cicada-editor/src/vendor/` 是上游 KiCad 源码的裁剪副本，遵循其原始许可。本仓库不含任何凭据：密钥一律通过环境变量或被 gitignore 的本地文件提供。

## 4. 构建与运行

```powershell
# 引擎（MSVC x64；需要本地 KiCad/vcpkg 依赖与 third_party/）
.\cicada-editor\scripts\m1b-rebuild.bat

# 一键窗口栈（引擎 + AI 宿主 + 产品窗口）
.\cicada-editor\scripts\start-cicada-app.bat

# 启动器（Electron）
Set-Location cicada-shell
npm install
Set-Location ..
.\cicada-editor\scripts\start-cicada-shell.bat
```

> PowerShell 5.1 不支持 `&&`：命令之间用换行或 `;`。脚本本身是 `.bat`，在 PowerShell 里直接调用即可。

坐标系约定：引擎与 JSON 一律 **IU 整数（0.01mm）**，前端渲染层才换算缩放。
